As a member of the DFIR team, you're tasked with investigating a ransomware attack involving Akira ransomware that has impacted critical systems. You’ve been provided with a memory dump from one of the compromised machines. Your goal is to analyze the memory for indicators of compromise, trace the ransomware’s entry point, and identify any malicious activity to assess the incident and guide the response strategy.

#### ❔  1: While analyzing the memory dump, identifying the compromised machine's network domain affiliation is a crucial step in understanding the attack's scope. What is the domain to which the infected machine is joined?

$${\color{purple}__Objective__}$$

Determine the Active Directory domain affiliation of the compromised system from the memory image. Establishing domain membership is an important early step in ransomware investigations because it helps define the attack scope, identifies potentially affected systems, and provides context for authentication, privilege escalation, and lateral movement activities within the environment.

$${\color{red}__Analysis__}$$

The investigation began by reviewing the contents of the provided Start Here directory. This initial review is a common DFIR practice because challenge authors and incident responders often include guidance, tools, or artifacts that assist with the forensic workflow. The included notes recommended extracting Windows Event Logs from memory and processing them using specialized event log analysis tools.

To identify the system's domain membership, Windows Event Logs were extracted directly from the memory dump using Volatility3 and the windows.dumpfiles plugin. The extraction targeted .evtx files residing in memory, recovering several Windows log sources including Security, System, Application, PowerShell, and other operational logs.

After recovering the Security event log, EvtxECmd was used to parse the extracted .evtx data and convert it into CSV format. Converting the logs allowed for easier analysis within Timeline Explorer, which provides a structured view of event log records and metadata.

Reviewing the parsed Security log entries in Timeline Explorer revealed the Computer field associated with the audited events. The hostname was recorded as Shareserver.Cydef.enterprise, indicating that the compromised system was joined to the Cydef.enterprise Active Directory domain. This artifact provides reliable evidence of domain affiliation because it originates directly from Windows Security Auditing events generated by the operating system.

#### ❔  2: Identifying the shared file path accessed by the attacker is crucial for understanding the scope of the breach and determining which files may have been compromised. What is the local path of the file that was shared on the file server?

$${\color{purple}__Objective__}$$

Identify the local file system path associated with a network share configured on the compromised file server. Determining the location of shared resources is a critical step in ransomware investigations, as attackers commonly target network shares to access, encrypt, or exfiltrate organizational data.

$${\color{red}__Analysis__}$$

To determine which files or directories were exposed through file sharing services, registry artifacts were extracted directly from the memory image. Windows stores SMB share configurations within the SYSTEM registry hive, making registry analysis an effective method for identifying shared resources even when disk access is unavailable.

Using Volatility3, the registry hives were enumerated and dumped from memory. The output included several important hives, such as SYSTEM, SOFTWARE, SAM, SECURITY, and NTUSER.DAT. The SYSTEM hive was selected for further analysis because it contains service configurations and network share definitions managed by the Windows SMB server.

The extracted SYSTEM hive was loaded into Registry Explorer, where the following registry location was examined: _ROOT\ControlSet001\Services\LanmanServer\Shares_

The LanmanServer service is responsible for providing SMB file-sharing functionality. Within the Shares key, registry values define the names and corresponding local paths of shared directories available over the network.

Reviewing the share configuration revealed the entry _Path=Z:\Shares\data_, identifying the local directory associated with the network share. This path represents a potentially high-value target during the ransomware attack, as shared directories are often used to store business-critical files accessible by multiple users across the domain.

#### ❔  4: Identifying the process name of the attacker's tool is key to tracking their actions. What is the process name of the tool used by the attacker to remotely execute commands and perform malicious activities on the compromised FileServer? Tip: Check both active and terminated or hidden processes in the memory capture.

$${\color{purple}__Objective__}$$

Identify the process used by the attacker to remotely execute commands on the compromised file server. Determining the remote administration tool leveraged during the intrusion helps investigators understand the attacker's methods, reconstruct lateral movement activity, and identify systems that may have been accessed using the same technique.

$${\color{red}__Analysis__}$$

To identify the attacker's remote execution mechanism, registry artifacts extracted from memory were examined for evidence of service creation and deleted records. Attackers frequently use legitimate administrative tools such as PsExec to execute commands remotely, and traces of these tools often remain in the registry even after the associated services have been removed.

The previously extracted SYSTEM hive was loaded into Registry Explorer, with particular attention given to the Associated Deleted Records section. Deleted registry records can provide valuable evidence of attacker activity because they often contain remnants of temporary services, persistence mechanisms, or execution artifacts that no longer exist in the active registry structure.

Within the deleted records under: _ROOT\ControlSet001\Services_

a deleted service entry named PSEXESVC was identified. Examination of the service configuration revealed an ImagePath value of: _%SystemRoot%\PSEXESVC.exe_

The service's last write timestamp closely aligned with the failed logon activity identified in the previous investigation step. Correlating these timestamps strengthens the conclusion that the attacker attempted authentication against the server and subsequently used PsExec to execute commands remotely.

PsExec is a legitimate Microsoft Sysinternals administration utility frequently abused by threat actors for lateral movement and remote code execution. When executed remotely, PsExec creates the temporary PSEXESVC service on the target host, making the presence of this service a strong indicator of remote administrative activity.

#### ❔  8: Understanding how the attacker leveraged specific system files is crucial, as it can reveal their methods for accessing sensitive data and escalating privileges. What DLL file did the attacker use in the PowerShell command to dump the targeted process for further exploitation?

$${\color{purple}__Objective__}$$

Identify the DLL leveraged by the attacker to create a memory dump of a sensitive process on the compromised system. Understanding the tools and techniques used for credential access is essential because attackers frequently dump process memory to extract passwords, NTLM hashes, Kerberos tickets, and other authentication material that can be used for privilege escalation and lateral movement.

$${\color{red}__Analysis__}$$

After identifying the attacker's use of PsExec for remote command execution and observing multiple PowerShell-based administrative actions, the investigation continued within the Sysmon Operational Event Log to identify commands associated with credential theft or memory dumping activities.

Using Timeline Explorer, the Sysmon events were filtered to focus on Event ID 1 (Process Creation) and Event ID 13 (Registry Modifications), which had previously proven useful for identifying attacker commands. To narrow the search, the event data was queried for references to .dll files, as attackers often abuse legitimate Windows DLLs to perform sensitive operations while avoiding the need to deploy external tools.

This search revealed a PowerShell command executed through PSEXESVC.exe that launched rundll32.exe with the following parameters:
_rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump ((Get-Process lsass).Id) C:\Windows\temp\lsass.dmp full_

The command uses the MiniDump export within comsvcs.dll to create a full memory dump of the LSASS (Local Security Authority Subsystem Service) process. LSASS contains highly sensitive authentication data, making it a frequent target for attackers seeking credential material.

The use of _comsvcs.dll_ is a well-known "living-off-the-land" technique because it relies entirely on legitimate Windows components. By abusing a trusted DLL already present on the system, the attacker can perform credential dumping without introducing additional malware binaries, reducing the likelihood of detection.
